## 2026-11-26 · 刷回真 MF-INK + 一键刷机脚本 · Claude
- 做了什么:用户嫌 MoInk 配套软件难用,把新板(COM29)从 MoInk 刷回真 MF-INK V1.0.4(4MB 整包,热点 MF-INK-248C);擦除+写入+Hash 校验全过,`/api/info` 正常返回。随后做了一套双击即刷的脚本:核心 `scripts/flash_mfink.py`(自动探测 ESP32-C3→擦除→写入→校验)+ `一键刷MF-INK.bat`(仓库根目录+桌面各一份)。
- 为什么这么做:真 MF-INK 自带 SoftAP + 网页界面,连热点开 `192.168.4.1` 就能推图,省掉 MoInk 那套配置;把"擦除/写入/校验/探测端口"打包成一键,避免每次记命令和选错固件。
- 怎么理解:这是**工具层**交付,不改固件源码、不解决刷屏硬件问题。脚本只认 `mfink_V1.0.4_merged.bin`(4,194,304B),刻意避开 1,198,592B 的误标 InkSight 固件。探测到的"没串口"是保护逻辑(幽灵设备/未上电打不开),不是脚本故障。
- 教育内容:① 同名固件要看字节数/热点名辨真伪——真 MF-INK 是 4MB + 热点 `MF-INK-XXXX`,误标的是 ~1.2MB + `InkSight-XXXX`,刷错就重现中间杠。② Windows 上 .bat 必须 GBK 编码 + CRLF 换行,中文注释/echo 才不会在 cmd(码页936)里变乱码被当命令执行;用 Python 显式 `.encode('gbk')` + `\r\n` 落盘,不能用普通写文件。③ 串口探测用"实际能否 open"来判断板子在不在线,比设备管理器列表更可靠(幽灵设备 Code45 会列出来但打不开)。④ 子进程输出用 `capture_output` 收字节再手动 `decode('utf-8','replace')`,避免非 UTF-8 输出在子线程抛 UnicodeDecodeError。
- 产出(路径):scripts/flash_mfink.py · 一键刷MF-INK.bat(仓库根+桌面) · README.md 更新"怎么跑"
- 问题 → 怎么解决:写脚本后第一次 `--check` 探测失败,查到是板子 USB 从总线整个掉了(PnP 里 303A 设备数=0),非脚本问题;顺手把报错提示改成"正常保护+重插指引"并加 `--port` 手动兜底。
- 下一步(交接棒):用户重插板子后跑 `python scripts/flash_mfink.py --check` 验证自动探测,确认后即可双击 bat 自刷;屏幕刷新问题(FPC 硬件层)仍待单独处理。
